# 汎用ノード候補一覧 — IME 実装前／IME 実装後

- 状態: **アイデアの棚卸し・未採用**（標準実装を約束しない）
- 対象: ノード作者が独自実装可能で、DIY_IME2側で共通提供すると便利かもしれない**汎用ノード候補**。正式な用語定義は[ノード分類](node-classification.md)を参照。
- 区分: **用途でなく実装フェーズ**。「IME 実装前」は文字列変換エンジンだけで試せるもの。「IME 実装後」はキー入力・未確定状態・イベント・UI・OS 連携などを前提とするもの。
- 件数: IME 実装前 **142** 件、IME 実装後 **116** 件、計 **258** 件。

> 本一覧は候補の**網羅的な洗い出し**であり、採用・優先順位・実装方法・ノードの厳密な分割粒度は未決定。似た項目の統合や名称変更を許す。列挙した汎用候補は、今後**プリミティブノード**または**標準機能ノード候補**として整理できる。正式採用を意味しない。システムノード（Input、Output、Spec、将来のUI等）の仕様とは分けて扱う。
>
> IME 実装前の**文章変換**で使うデータの共通形式は Text / Sequence / Choice の候補木。LLM埋め込みなど文章以外の値が必要なノードには、適切な追加型を**その機能の設計段階**で定義する。IME 実装後もこの候補木への固定は要求せず、イベント・状態などの新型を追加できる。

## 今後の整理時の基準

1. この段階では項目の**採否や必要性を確定しない**。
2. 各項目の詳細設計を行う際に、汎用機能かシステム権限が必要な機能かを検証する。
3. 複数項目が同じ処理で実現可能なら統合してよい。反対に高度な項目はさらに分割してよい。
4. ノード作者の独自実装可能性を残す。「ノードで解決できることはノードで解決する」という原則を維持する。
5. 文字列変換、キー操作・IME化などの段階ごとの設計境界は [コア設計仕様](core-architecture-v0.1.md) に従う。
