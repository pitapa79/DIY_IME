# DIY_IME 性能目標

DIY_IME の性能は、**ユーザーが作る IME の自由を制限するためではなく、DIY_IME 自身がその自由の足を引っ張らないことを確認するため**に評価する。

この文書の数値は、現時点の設計目標であり、ユーザーが作成する IME に対する強制制限ではない。Windows TSF 統合後の実測を踏まえて見直してよい。

## 1. 主指標: Reference IME Latency

最も重要な指標は、DIY_IME 上で構成できる **最軽量かつ実用的な IME** の応答時間とする。

コア単体の速度だけでは、ユーザーが実際に使う IME の応答性を表せないため、こちらを主目標とする。

### Reference Minimal Practical IME

基準構成は、少なくとも次のような通常の日本語入力に必要な処理を含む。

```text
Input
  ↓
ローマ字 → かな
  ↓
辞書変換
  ↓
候補選択
  ↓
Output
```

単なる `Input → Output` のような実用性を持たない構成は、Reference IME Latency の基準には使わない。

辞書についても、ごく小さなテスト辞書ではなく、実用規模の辞書を使うことを目指す。正式な辞書形式と具体的な語数は、辞書仕様が確定した段階で固定する。

### 暫定目標

通常入力時の、DIY_IME が入力を受け取ってから出力結果を OS 側へ返せる状態になるまでの時間について、

- **P95 < 10 ms**
- **P99 < 20 ms**
- 50 ms を超える応答は、通常動作では原則として発生させないことを目指す

この数値はユーザー構成への上限ではない。ユーザーが LLM、外部 API、大規模辞書、重い解析などを組み合わせてこれを超える IME を作ることは許容する。

測定対象は原則として DIY_IME の処理区間とし、物理キーボード、ディスプレイの走査、アプリ側の描画など、DIY_IME が直接制御できない遅延は分離する。

## 2. 補助指標: Core Overhead

Reference IME Latency とは別に、DIY_IME Core 自身が追加する純粋なオーバーヘッドも監視する。

対象の例:

- グラフの実行管理
- ノード間ルーティング
- Packet / 型の受け渡し
- 実行順制御
- 状態管理
- 必要な境界変換

変換アルゴリズム、辞書検索、LLM 推論など、ノード自身の意味的な処理時間は Core Overhead から分離して考える。

### 暫定目標

通常入力相当の小さな実行について、

- **Core Overhead P95 < 1 ms** を目標とする
- Reference IME Latency の時間予算の大部分を、ユーザーが選んだノード処理へ残す

1 ms は現時点の工学上の目標値であり、API や互換性を犠牲にして絶対達成すべき値ではない。実測と設計上のトレードオフを踏まえて更新する。

## 3. 二つの指標の関係

性能判断では、次の優先順位を使う。

1. **Reference IME Latency** — ユーザーが最小実用 IME を作ったとき、実際に十分高速か
2. **Core Overhead** — その時間のうち、DIY_IME 本体がどれだけ消費しているか

例えば Reference IME Latency が 10 ms でも、そのうち Core が 6 ms を消費しているなら好ましくない。逆に Core が 0.5 ms で、残りを変換・辞書・候補処理に使えているなら、DIY_IME 本体は十分小さな負担に収まっていると考えられる。

## 4. 性能目標と設計思想

性能目標のために、ユーザーが作成できる IME の種類を制限してはならない。

✕ 「10 ms を超えるノードは禁止する」  
◯ 最小実用構成では高速に動作する基盤を提供し、重い構成には経過時間、タイムアウト、分岐、フォールバックなどの制御手段を提供する。

✕ Core のベンチマークを良くするために、交換可能な処理を本体へ固定する。  
◯ 交換可能性を維持したまま、Core Overhead を測定して改善する。

つまり、性能目標は **ユーザーの自由を削るための制約ではなく、DIY_IME 側に課す品質目標** とする。

## 5. 現在のベンチマークとの関係

[Coreの入力長別ベンチマーク](runtime-benchmark.md) v2は合成ノードによる実行管理の計測で、変換処理や本書のReference IME Latencyではない。[実配布Wasmグラフの計測](security/wasm-application-benchmark.md)は、別途、小さな同梱辞書グラフの初回・準備・通常変換と実処理終了を実アプリで計測する。これも正式なReference IME Latencyとは区別する。

Core計測は変換処理を含まず、実配布Wasm計測も小さな同梱テスト辞書と固定ケースに限られる。どちらもWindows TSF・実用規模の辞書や候補数を含まないため、Reference IMEの正式な性能試験は別途定義する。

将来的には少なくとも次を分離して測定する。

- Reference IME Latency
- Core Overhead
- 各ノードの実行時間
- OS 接続部分の遅延
- 必要に応じて end-to-end のキー入力から表示までの遅延
