# ブリッジの応答待ち時間

ホストの環境変数 `DIY_IME_BRIDGE_RESPONSE_TIMEOUT_MS` で、コアへの送信後に応答を待つ時間を指定する。
未設定時は既存どおり **10,000 ms**。設定は開発・プレビューサーバーの起動時に読み取り、そのホストが作る全セッションと単発CLI呼出しに適用する。グラフやブラウザーの設定ではない。

## 設定方法

PowerShellで、`editor/` から起動する例:

```powershell
$env:DIY_IME_BRIDGE_RESPONSE_TIMEOUT_MS = '60000'
npm run dev
```

無期限に待つ場合:

```powershell
$env:DIY_IME_BRIDGE_RESPONSE_TIMEOUT_MS = 'unlimited'
npm run dev
```

有限値は **1〜2,147,483,647** の整数ミリ秒（ASCII数字、先頭ゼロなし）。上限はNode.jsのタイマーが扱える最大値で、約24.9日。正のJavaScript安全整数であることも検査する。空文字、0、負数、小数、指数表記、符号、前後の空白、別の大文字小文字、上限を超える値は起動時にエラーにする。巨大値をタイマーへ渡して短時間に丸めさせない。

`npm run preview` にも同じ設定を使う。起動後の環境変数変更は反映しない。変更するにはホストを再起動し、画面から再接続して計画を準備・切替する。

## セッションの寿命

応答待ちタイマーは要求をコアへ送るときに開始し、その要求が完了・失敗したときに解除する。送信待ちの時間は含めず、各要求を直列に送る。有限の待ち時間を超えると子プロセスを終了し、セッション全体を無効化し、待機中の要求も拒否する。単発CLI呼出しも設定した待ち時間で終了する。

`unlimited` が無効にするのは応答待ちタイマーだけ。要求1 MiB・応答8 MiBの上限、形式・プロトコル検査、送信前取消、送信後切断、子プロセス終了の検出と後始末は維持する。無期限でも、タブやサーバーの終了・明示的な切断によってセッションは終了する。

送信中または送信待ちの要求があるセッションは、15分未使用の終了対象にしない。最後の要求が完了した時点から未使用時間を数え、以後15分を超えたセッションを1分ごとの検査で終了する。画面からの状態確認も要求として扱う。

## 制限と戻し方

これはブリッジ全体の通信応答待ち設定。ノードごとの処理期限、フォールバック、非同期処理・実行中取消の契約を追加するものではない。

送信後の切断や有限タイムアウトでは処理結果が不明になる。要求を自動再送せず、再接続は空のEngineから始める。外部への副作用を取り消したり、前の状態を自動復元したりしない。

既定の10秒に戻す場合は、ホストを停止してから環境変数を削除し、再起動する:

```powershell
Remove-Item Env:DIY_IME_BRIDGE_RESPONSE_TIMEOUT_MS
npm run dev
```

同じホストが持つセッションは再起動で終了するため、画面から再接続し計画を準備・切替する。
