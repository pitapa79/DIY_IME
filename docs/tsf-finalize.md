# TSFの確定と取消

[#196](https://github.com/pitapa79/DIY_IME/issues/196) は開始main `bf5baac02319c9a245430ac1ce5d1134ad287e3b` の候補操作を現在文書への確定につなぐ。

- 候補が表示中のEnterは、選択中の未確定範囲を確認してTSFのcompositionを終了する。表示済みの文字列を再挿入しない。候補がないときは、準備済みHostに原文を `finalize` として渡す。診断構成でHostが利用できないときは、現在の原文を確定する。
- 確定結果は現在の入力世代、フォーカス、保護状態、所有範囲と一致した場合だけ反映する。変換中の繰り返しEnterは同じ要求を待つ。確定後のEnter・Esc・Backspaceはアプリへ渡る。
- キャンセル・入力更新・フォーカス変更・外部終了で旧要求を失効する。書き込み編集セッションが開始できなければ同じ文書でユーザーが再試行できる。変更の成否を確認できない場合は所有権を失効し、同じ結果を再適用しない。
- テストでは候補選択後の確定、編集ロック拒否後の明示再試行、`n` のfinalize、繰り返しEnter、確定済み本文に対するEsc、文書切替時の取消を検査する。自動・手動保護と実アプリの総合受入は #197、#198 で扱う。
