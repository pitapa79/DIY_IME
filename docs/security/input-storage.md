# 入力本文の任意保存（#230・IME化前の既存Editor修正）

開始main `1cff347702828ac5af05d7b12dc4294243b939b4`。
通常入力を毎回localStorageへ保存していた既存hookを修正し、
「実行時入力をこのブラウザーに保存」を利用者が選んだ場合だけ永続化する。
既定はOFF。接続の作り直し中は同じページ内メモリに入力を保持する。
Graphの下書きと実行時入力は引き続き別データで、Graph保存へ本文を混ぜない。

明示的な選択の記録がない旧入力は復元せず、hookの起動時に旧保存キーを削除する。
OFFに戻すと選択の記録を先に失効し、本文を削除して、その後の入力を保存しない。本文削除だけが失敗しても、次回に旧本文を自動復元しない拒否系を検査する。
ONの場合だけ不正Unicodeや採番上限も元のまま復元し、従来の明示修復を可能にする。
別タブから選択が撤回された場合も保存を止める。保存/削除失敗は成功表示にせず、
メモリ内の入力・採番を壊さない。閲覧履歴、OS cache、ブラウザーのバックアップや削除済みbytesの消去までは保証しない。

これは既存Editorの保存制御であり、パスワード欄の検出、保護入力ゲート、Node間の隔離、
秘密ストア、暗号化、OSレベルのログ抑止を実装したとは扱わない。
今後#223の保護入力を接続する際は、保存選択にかかわらず保護入力を保存しない信頼側経路が必要。

## 常駐Hostの診断境界

既存v2/v3の子プロセスstderr末尾は保持せず排出だけにし、終了時のHTTPエラーへ転載しない。
偽子プロセスが出した入力/鍵canaryが別の終了応答へ混入しないことを検査する。
構造化Node診断と単発CLIの既存エラーは利用者向け表示を維持しており、秘密を含み得る。
全診断の匿名化・秘密検出・OS側ログ禁止を保証しない。
