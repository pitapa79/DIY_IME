# 公開Windows配布版の基本診断の待ち時間

2026-11-05（JST）に、[Issue #7](https://github.com/pitapa79/DIY_IME/issues/7) の計測を完了しました。基本記録のP95増分5%目標を3群中2群で超過しました。

| 群 | OFF P50 / P95 / P99（ms） | 基本 P50 / P95 / P99（ms） | P95増分 |
| --- | ---: | ---: | ---: |
| 1 | 4,278 / 6,596 / 7,302 | 4,320 / 6,153 / 7,269 | −6.71% |
| 2 | 4,229 / 9,195 / 10,233 | 4,312 / 10,877 / 15,275 | +18.29% |
| 3 | 4,308 / 6,169 / 7,744 | 4,460 / 6,815 / 8,754 | +10.47% |

同じ固定ケースを隣接する2回で実行し、先行モードを均衡させました。各群100ペア、計300ペア600件です。分位点は群・モードごとに100件からnearest rankで計算し、表は表示時に丸めています。起動後の初回と予備実行は集計外です。入力更新前から、結果が確定して4種類の物理実行数がゼロと観測するまでを計測しました。Run照会間隔の設定は5 ms、実行中の基本記録の照会は150 msです。

300個のペアファイルと照合し、固定ケース・実行順序・分位点を再検算しました。全出力、物理終了、再起動と終了、配布ファイルのハッシュ検査が通過し、基本記録の欠落は0件でした。記録・集計の手順は[配布Wasmグラフの計測](wasm-application-benchmark.md)に従いました。

OFFでもP95は群間で6,169〜9,195 msに変動しました。この測定では群内の時間変動と記録処理の寄与を分離できません。数値の範囲は同梱小辞書グラフのループバック実行です。[Reference IME Latency](../performance-goals.md)の評価には実用辞書、描画、Windows IMEの入力経路を含む別の測定が必要です。
