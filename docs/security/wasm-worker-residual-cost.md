# JIT除去後の隔離Workerの費用

[Issue #26](https://github.com/pitapa79/DIY_IME/issues/26) の調査。基準は公開main `8fde01af6fd64aefb30a01df9bf3f5805469638a`、[Windows CI 42155771450](https://github.com/pitapa79/DIY_IME/actions/runs/42155771450)、配布artifact `13474977409`。配布Hostの診断では28 Workerで欠落0、DLL検証・ロード21.5〜24.2 ms、Hostプロセス43.1〜50.0 ms、隔離準備6.9〜17.5 ms、清掃3.6〜4.4 msでした。正答・全物理終了・closeを照合済みです。

## 実AppContainerでの切り分け

Windows x64で上記配布物を展開し、Rust 1.90.0 GNUの開発用probeを起動しました。

```powershell
$env:DIY_COMPILED_PROBE_BUNDLE = 'C:\path\to\windows-app'
cargo test --locked --lib isolated_worker::runtime::compiled_module_probe::residual -- --ignored --exact --nocapture
```

同じ親・子の実行ファイル、AppContainer、Job、資産リース、パイプで、32バイトを照合して固定の計数を返す対照と、先に固定DLLを完全検証しWindowsでロード・シンボル解決する試行を12ペア交互順で測りました。両側で元プロセスの実終了、出力、回収を確認しました。子はゲストを呼びません。初回と大きい観測値も集計に残しています。

| 区間 | パイプ対照の中央値（ms） | DLLありの中央値（ms） |
| --- | ---: | ---: |
| 親の隔離準備 | 27.20 | 25.31 |
| 親の起動処理開始から再開 | 19.42 | 16.78 |
| 親の再開から実終了確認 | 55.28 | 203.43 |
| 親の実終了後のパイプ回収 | 0.032 | 0.051 |
| 親の清掃（Job計数待ちを分離） | 12.52 | 13.11 |
| 子のDLL読み込み | — | 16.20 |
| 子のSHA-256 | — | 110.43 |
| 子の完全検証全体 | — | 130.37 |
| 子のWindowsロードとシンボル解決 | — | 6.92 |
| 子の短いstdin読み込み | 0.153 | 0.134 |

パイプ対照の再開から実終了の範囲は40.8〜219.5 ms、DLL完全検証は117.6〜1,970.9 msでした。最初のDLL読み込みで約1.81秒を観測しました。JobのCPU中央値はパイプ対照46.9 ms、DLLあり179.7 ms、ピークコミットは7.72 MBと29.00 MBです。親と子の区間は重なり、分位点も別です。表を合算しません。パイプ回収とstdin読み込みには子の初期化やプロセス終了待ちが含まれません。

ローカルの開発用バイナリーとCIの実配布版は環境・バイナリー・測定境界が異なります。短いパイプ対照は通常経路の実測値や理論下限として扱いません。配布HostのHTTP照会、グラフ、辞書、候補、文書、TSFはこの対照に含まれません。

## 判断

完全検証の中ではSHA-256が大きな費用です。一方、この端末ではDLLを外した対照でも、実終了待ちの最短観測が40.8 msでした。ハッシュ処理だけの高速化を10 ms級への単独の解決策として進めません。次は、新しい隔離Workerを入力前に準備したうえで、一度の配送から正答・元プロセス終了・回収までに残る費用を調べます。準備と補充の負担も同時に記録します。Workerを複数入力で再利用する方式は、現行の毎回の実終了保証との関係を別に評価する必要があります。
