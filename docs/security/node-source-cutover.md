# Main / Node source cutover

Main owns only `input.text`, `demo.packet`, `e2e.input` and `e2e.output`, the Node-independent runtime and trusted Host/brokers. Processing implementations are owned by [DIY_IME2_node](https://github.com/pitapa79/DIY_IME2_node/tree/e3179fb4293416e8de5a49060d209a257eec3c70). The captured migration inventory remains historical and unchanged; its old source paths are not a current Main file list.

The cutover removes 44 processing implementation/registration files and 43 transferred semantic test files from Main. All transferred test-function names were compared with the Node snapshot before removal. Node PR16 already passed Native348/doc2 and real Wasm/provenance checks. Main's Core files, contract JSON, compiled official data and captured inventory (118 blobs) remain byte-identical to the preceding validated source. There is no Main dependency on Node native source or a mutable SDK copy.

Production `register_builtin_nodes` now delegates to the four canonical system adapters. The actual CLI is tested to list exactly those four, run a system source and refuse old processing kinds before invocation. Processing graphs retain their kinds/versions/ports/configs and run through approved official Wasm packages in the application. This intentionally retires the old prototype CLI's implicit Native processing composition. No Native or weaker-isolation fallback is added. The normal React entry and Vite API are external-only; the bundled application was already external-only.

`src/cli.rs` contains registry-independent command transport. Protocol/control tests explicitly use the internal `diy-ime2-test-host` with synthetic fixtures under `tests/support`; it is not shipped. The fake-document harness uses a named, finite response table rather than a romanization algorithm, and retains its 22 ownership/commit/cancel tests. UI rendering tests use captured reports with artifact provenance. Actual processing assertions formerly embedded in legacy HTTP tests have moved into the real packaged-app check. The `runtime_benchmark` version2 measures synthetic Core transport only, not IME conversion latency.

Validation before submission: Main Rust510/doc5/fmt/clippy; Editor283 plus the existing skip1/types/build; full actual Wasm suites for catalog, manager, permissions, Host, dictionary, network/secret rotation and physical ending. The assembled-app check compares every actual definition with the captured 52-definition inventory, executes 19 saved demo/E2E/practical/snapshot cases (including eight compose/finalize romaji inputs, dictionary Unicode/tie/unknown/empty, Data/NoOutput/Error), and preserves explicit consent, saved reopening, true close and launcher-crash descendant ending. The same check rejects a bundle containing the synthetic test Host. Final exact-source CI and assembled candidate results belong in the PR.

Desktop visual/functional acceptance was completed at 1280×720 in a separate in-app browser using the actual Windows bundle and dedicated synthetic data. The initial Windows Chrome URL-confidence limitation remained untouched; no authentication window was operated. The UI check connected, reviewed nine subjects, granted this connection only, activated the graph, entered `kousui`, observed `降水` with physical counts zero and used the application exit control. It found and fixed a default-selection bug: the requested final output now takes priority over an unused intermediate `pending` output, while manual/connection choices remain authoritative. Primary results precede secondary permission/secret controls. Cancellation remains available until both logical completion and all physical counts are zero. Six added UI regression cases cover these behaviors.

TSF, hotkeys, Native isolation-off and public signing remain outside this Wasm milestone; current latency is still above practical IME targets. This browser check is not native IME acceptance or a claim to have automated the separate Chrome window.
