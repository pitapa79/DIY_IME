## 準備後に未使用の Worker を取り消す検査

ready-or-fallback の遅延比較は未実施。現行補充ハーネスは lane スレッドが `execute_observed` と準備通知・入力送信・回収を一括所有し、予定時刻に未準備の Worker を判定して取り消し、同じ物理枠の終了を確認してから代替を起動するスケジューラを持たない。実装には、準備途中の所有者と取消 token をスケジューラに公開し、物理終了・回収まで枠を予約したまま待ち、代替の起動をその後に許す状態機械が必要。さらに枯渇時に入力を待機・置換・破棄する条件を定義する必要がある。単に追加 Worker を起動すると同じ上限の比較にならない。

代わりに原本 JIT Worker が ready を通知した直後、入力を送らず取消し、OS の終了確認と Job / ACL / profile 回収を16回測定した。全16回で取消と物理終了を確認。取消から終了確認の P50 / P95 は12.62 / 18.21 ms、回収完了は18.55 / 24.99 ms。単体 Job CPU P50 は250 ms、Job ピークメモリ P50 は約44.2 MiB（各 Worker 単体）。準備完了から直ちに取消した検査であり、準備途中の取消、代替起動、予定時刻からの応答、入力の置換・破棄を測っていない。16件の P95 は最大値であり、デバッグ検査と合成 Wasm の範囲に限る。生ログは `issue86-generic-raw-idle-cancel.log`。

```powershell
cargo test --locked --lib cancel_generic_raw_idle_worker -- --ignored --nocapture
```
## 制御した未準備判定と1枠フォールバック

検査専用の1枠対照を追加した。投機 Worker が原本を JIT し実際には ready マーカーを送った時点で、その通知をスケジューラに渡さないよう試験が制御し、同時刻を入力到着として未準備扱いにする。投機 Worker を取消して OS の終了を確認し、Job と ACL / profile を回収した**後にのみ**同じ入力の通常 JIT Worker を起動する。対照は同一入力を投機なしで入力到着時に起動。16組を交互順に測り、32/32件の応答一致・通常 Worker の正常終了と、16/16件の投機 Worker の取消・物理終了を確認した。投機と代替を重複起動しない。

| 最終回収 | 84.76 / 1104.26 ms | 100.10 / 112.19 ms |

## 独立した latest-input-wins の2枠シミュレーション

試験専用スケジューラを追加し、1入力実行と最大1個の予備を同時に扱う。16入力を20 / 100 ms間隔で各方式2試行、対照→事前→事前→対照の順に送る。新入力は未配送の pending を置き換え、実行中の旧 revision を取り消す。完了イベントを処理した時点で最新 revision に一致するものだけを正答として採用し、旧 revision は superseded とする。入力の新着処理と完了イベントの順序はこの試験スレッドで決まり、予定時刻ではなく実際の新着処理時点で current を更新する。各 current の文字列を完全照合する。

| 間隔 | 方式 | 正答 / 全入力 | superseded | 事前 Worker へ配送 |
| --- | --- | ---: | ---: | ---: |
| 20 ms | 入力時起動 | 4 / 32 | 28 | — |
| 20 ms | 事前準備 | 6 / 32 | 26 | 10 / 32 |
| 100 ms | 入力時起動 | 31 / 32 | 1 | — |
| 100 ms | 事前準備 | 32 / 32 | 0 | 32 / 32 |

事前 Worker への配送数には、その後に置換された入力も含む。試験では枠数を2以下とし、キャンセルされた Worker は OS 終了の receipt と Job / ACL / profile 回収後の完了通知まで枠を保持する。全 Worker を終了・回収してから試行を終えた。予備の初回は最初の入力より180 ms前に開始する。入力時起動も、起動中に新着があった場合はその同じ未入力 Worker を待って最新入力を送り、ready を待てないからと別 Worker を追加起動しない。事前準備側も未準備の Worker を待ち、今回の条件では別の fallback 起動は0回だった。

これは通常 Host ではなく、試験用の単純な単段スケジューラである。新着と完了の観測順、入力取消、予約、権限・保護を本番と同一とはみなせず、予定時刻に対する遅延も含まない。標本は各条件32入力、20 ms の正答数は少ない。生ログ `issue86-generic-raw-latest.log` の応答時間は正答に限り、終了確認時刻から実際の新着処理時刻までである。

```powershell
cargo test --locked --lib compare_raw_latest_wins -- --ignored --nocapture
```
