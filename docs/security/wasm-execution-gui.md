# Installed Node consent and execution in the Editor

Issue #280 connects the [production execution Host](wasm-external-host.md) and [permission subjects](wasm-permissions.md) to the Editor. The normal React/Vite entry and packaged application are now external-only after #302/PR303; the old synchronous/v3 panels remain internal development fixtures. Processing semantics live in installed Wasm packages; this mode has only the four canonical system Nodes plus installed declarations. Unknown installed kinds appear in the library and remain editable through their declared configuration/JSON.

## Host setup

The trusted application launcher sets DIYIME2_EXTERNAL_HOST_CONFIG to a fixed configuration file for diy-ime2-external-host. The schema is documented in wasm-external-host.md. The package manager and execution Host must point to the same dataRoot. Browser requests never select an executable, configuration path, storage root, OS policy, Worker or runtime DLL. The same-origin loopback bridge uses its fixed target/debug/diy-ime2-external-host.exe in this development setup. The packaged launcher now supplies the bundled binaries, fixed configuration and official packages; see windows-application-distribution.md. End users do not build with Git/Cargo.

The existing DIYIME2_NODE_MANAGER_CONFIG independently enables package management. Import through “ノードの導入”, connect to the installed-Node execution panel, and update the Node list after imports/updates. Build a graph and choose “グラフを確認”. The Host validates the exact installed code/configs in isolation and returns its immutable review. Select the execution and source output-port → destination operations, then choose ThisSession (“今回だけ”) or Saved. ThisSession expires on Session/connection closure. “このグラフへ切替” is separate and enabled only when all required operations are approved. Matching saved subjects require no new approval; changed code/config/input routes need new subjects. Input snapshots and keystrokes are separate from preparation and permission subjects.

Select requested outputs and, optionally, a positive run deadline in milliseconds; empty means no run deadline. No automatic prepare, approval, or start is performed. Use the runtime input fields and explicitly run the approved graph. Existing Core admission/physical ownership policy still applies. The Node list is a declaration catalog, not a claim that unsupported capabilities are available: live preparation refuses any capability that the configured dictionary/network/secret brokers do not support.

Manual protection immediately hides delivered data and withdraws the local context. The Host cancels and invalidates its sealed binding. Turning protection off does not restore the old graph or result. Reprepare before execution. OS protected-input automatic detection is not implemented. Current Session-only and saved subjects can be revoked individually; saved fingerprints from earlier reviews are also listed. Current review labels identify known subjects, while older saved subjects are shown by fingerprint. Runtime input and result payloads are never stored in the permission book.

## Connection and publication ownership

/api/external/connections creates one opaque random 128-bit connection lease. Another owner is refused while it is active or ending. Requests and DELETE address that exact lease. Old/late cleanup cannot close a new owner. DELETE withdraws the lease before awaiting cooperative Host EOF/close, retains the closing slot until actual process ending and never force-kills or silently respawns. Abnormal ending or malformed transport permanently refuses new Host creation in that application instance. Explicitly restart the application after diagnosing that failure; old graph/context is never restored.

The shared bounded framed client preserves pending ownership after HTTP abort until Host settlement/exit. Fast cancellation, protection and revocation can bypass the one ordinary operation slot, with at most 16 outstanding requests. The HTTP pool has an additional generation fence: data from an ordinary operation cannot be sent after a racing control invalidates that generation. Root fields and automatic-protection overrides are refused by the HTTP allowlist and strict Rust protocol. Transport frames use Host-selected request/response bounds. A too-large request leaves no pending entry; if a close frame cannot fit, EOF still cooperatively closes/drains the Host.

The GUI separately fences delivered results by owner/generation, actual Core epoch, graph identity, applied configuration, runtime-input snapshot/revision, Core delivery generation, current status and protection/uncertainty. Input or graph edits hide old data during render. Input revision is invalidated on the Host without preparation/approval. The immutable start key survives input edits and lost responses. Unknown starts are queried using getStart, never resent. Old snapshots are rejected by run key and event sequence. A failed status/query hides retained data until context can be confirmed; it does not restart or replay the run. Protection, revoke, disconnect, pagehide and unmount withdraw local buffers. pageshow does not reconnect automatically.

A cancel acknowledgment means cancellation requested; resource/Worker counters and physical ending are separate. Graph preparation and connection ending retain ownership until genuine termination. There is no timeout/kill fallback that frees an occupied slot.

## Validation

DOM tests cover explicit per-operation approval, saved reuse, immediate hiding on input/graph edits, unknown-start query without resend, manual protection/unprotect, late payload suppression, Session-only revocation, failed status, pagehide and true-ending disconnect. App regression covers adding an unknown installed kind and returning to the existing mode. Typed API tests reject forged/extra review fields, wrong run keys, unsafe null payloads and distinguish known denial from unknown response. Mock HTTP tests verify fixed process options, origin/operation authority refusal, control publication fencing, closing ownership, stale lease cleanup and abnormal-ending refusal. Framed-client tests cover size refusal/recovery and EOF close fallback.

external-real.test.ts uses the real HTTP server, typed browser client, production Host and actual AppContainer Worker: import, approval refusal, Saved reuse, real input flow, start query, stale payload withdrawal, infinite-work protection/true ending, revoke, reconnect with old-lease cleanup and live-work disconnect. Existing v2/v3 tests and formal fixtures remain unchanged in meaning.

Browser visual QA remains incomplete. The local computer-use tool previously stopped because it could not confidently determine the browser URL, and local browser automation is disabled in Work settings. No bypass UI actions were used. DOM, build and actual HTTP/OS-isolation checks are the available evidence; they do not replace a visual Windows review.

Dictionary/network/API-secret brokers, official package production/bundling/cutover, release performance and OS IME integration remain separate follow-ups.
