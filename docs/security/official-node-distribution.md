# Pinned official Wasm distribution and catalog setup

Issue #296; part of #257. The producer lives in [DIY_IME2_node](https://github.com/pitapa79/DIY_IME2_node/pull/16). Main contains compiled distribution data, not a new processing Rust dependency. The selected source is commit `ed6c97cd8bc22a2a26b4bc71c141fbc4f20e936e`, an ancestor of merged Node PR16. That exact source build was tested before subsequent documentation/test-helper changes.

`distribution/official` stores one default-feature release Wasm, the 48 original raw manifest byte sequences, original index and build receipt. This avoids storing 48 identical module copies. The loader reconstructs the exact original DIY2NODE frames and checks every original frame digest/size, aggregate size, kind/version/identity, inventory classification/status and module identity. Source repository/commit, index, receipt and module hashes are compiled into Main from pin.json. Replacing the on-disk pin file or supplying an imported index cannot create official status. The index is not a signature or a runtime grant.

The selected module uses Rust1.90.0 and public source/registry path remapping; its actual normal/AppContainer ABI, all48 complete definitions and original packages were checked. The build receipt records the exact artifact hashes. This is an explicit artifact/source pin, not a claim of bit-identical compiler output on every machine. Runtime/configuration proof remains mandatory.

## Fixed Host operation

The launcher may add an absolute `officialRoot` to the existing trusted ManagerConfig. Browser requests and package manifests cannot choose that root. Without it, setup returns `official-unavailable`. Existing configuration remains valid. A framed request with operation `{ "method": "bootstrap" }` has no upload payload, paths, policy overrides or approval flags. Unsolicited payload is refused and the connection closes under the existing framing rules.

One setup call installs at most16 missing packages, within the configured byte bound. Every selected package passes the existing actual isolated describe/default-config verification, Catalog review and atomic commit. It accepts only New changes; a concurrent import cannot turn setup into upgrade/rebuild consent. Subsequent calls resume from stored objects. The report includes sourceCommit, installed/present/pending IDs, conflicts, complete and executionPermissionGranted=false. A complete=false report with no pending IDs means existing entries need explicit user review; callers must not retry forever.

An exact present package is re-read and framing/digest/manifest verified. Corrupt or missing stored objects fail rather than being silently repaired. A different existing same-ID package, including an older version, or a different package with the expected kind is preserved and reported. Unrelated user packages are retained. There is no automatic downgrade, upgrade, rebuild or replacement. A later explicit import uses the normal GUI review and confirmation.

Cancellation uses the existing manager request token and isolated Worker ending. Cancellation before commit produces no new visible batch. A committed earlier batch remains and is reused after restart; an atomic commit already in progress can finish. Catalog revision guards reject concurrent changes. Setup never grants Node execution, input flow, dictionary reads, network or secrets. It does not invoke Prepare or processing with user input. Supported dictionary declarations can be installed before binding resources; runtime still requires the fixed provider and explicit approval. Isolation failure refuses installation with no native fallback.

## Verification and remaining distribution work

Unit tests reconstruct all48 exact original frames and check cancellation/selected bounds, same-ID/same-kind preservation and imported-index rejection. `scripts/check-official-bootstrap.mjs MANAGER HOST WORKER DLL OFFICIAL_DIRECTORY RESOURCE_CONTRACT` tests first install, process restart after16, idempotent no-op/catalog revision, stored-object corruption, preservation of an older existing same-ID package, cancellation and the real registered romaji/dictionary/select/stringify graph. The graph checks exact52 definitions, all9 input/execution/resource subjects, Unicode/ties/unknown/empty Data and saved permission reopening. Assets are local, with no cross-repository checkout or token. CI runs this with the other real Wasm checks.

The old in-Main processing copies remain until the compiled application distribution and default external cutover are verified. This change is the safe catalog bootstrap backend. The complete offline Windows launcher/static GUI, user-facing bootstrap progress/conflict handling, default external execution, release performance and combined/visual QA are subsequent work. It does not implement TSF, hotkeys, Native isolation-off or public signing.
