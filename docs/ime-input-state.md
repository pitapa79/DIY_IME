# IME入力状態と文書編集境界

[#190](https://github.com/pitapa79/DIY_IME/issues/190) は [TSF接続契約](tsf-stage-b-connection.md) の信頼側状態を非公開の作業用クレート `diy-ime2-ime-host` に置く。開始mainは `34d1662c8b7b79f80c7a6505ca6b7a2ac7f46f9d`。CoreのRuntimeInput、実行キー、Node/Graph/Packetの公開契約を使用する。

## 接続時の役割

- TSFアパートメントは文書と選択範囲の世代を管理する。同じContextに戻る場合も新しいフォーカス世代を発行し、編集や選択の変更、新しい保護判定を状態機械へ反映する。OS側の所有権、edit cookie、編集可能なrangeはアダプターが管理する。
- 状態機械は全文compose/finalizeと単調増加のrevisionを用意し、最新要求だけが配送可能になる。Hostの受理応答に実行キーを束縛し、結果の受取と適用で要求・実行キー・保護世代・対象文書を照合する。未確定中の計画切替は拒否する。
- 書込み前に付与済み編集セッションから対象範囲のUTF-16だけを検査する。アダプターは現在の対象・所有・保護を照合し、書込み直前にも確認する。空Textは結果として扱う。NoOutputや異常出力は編集を起こさない。空確定で書き換えられる範囲は所有する未確定範囲に限る。
- 未書込みと断定できる失敗は、同じ要求・対象に対する再試行を許す。成否不明の場合は結果を破棄し、同じ文書スナップショットを閉じる。旧範囲の推測による取消や再確定は行わず、再取得した対象と新規入力で再開する。
- 取消、保護、対象変更はまず配送を閉じ、要求と入力を失効する。必要な片付けは安全に再確認できた旧compositionだけを対象とする。複数の失効が重なっても、古い応答が最新の保護を解除することはない。失効処理に失敗した場合は、成功を確認するまで閉じたままにする。
- 実行Hostとの接続では、取消・失効の要求をTSFスレッドの外へ渡す。送信待ちの本文も失効できるようにし、Hostへ引き渡す境界で保護を再照合する。失効の完了と実行プロセスの物理的な回収は別に管理する。

## 検査範囲

`cargo test --locked -p diy-ime2-ime-host` の偽文書では、遅延と重複、他の実行キー、同一文字の再入力、保護遷移、未書込みと書込み後の失敗、選択変更、UTF-16、確定の一回性を検査する。既存の保護・実行セッション・出力境界検査も維持する。実際のTSFイベント、OS登録、編集セッション、キー配送と非同期Host接続の検証は [後続Issue](tsf-stage-b-connection.md#実施順と検査) で行う。
