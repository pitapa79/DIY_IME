# Windows IME化への工程

基準日: 2026-11-04。計画Issue [#314](https://github.com/pitapa79/DIY_IME2/issues/314)。
これは実装の依存順序と完了判定であり、全工程の実装完了を示さない。
引継ぎ [#311](https://github.com/pitapa79/DIY_IME2/issues/311) は当時の記録として扱い、各作業の開始時に最新main・Issue・実装を照合する。

**今回の作業範囲はIME化の開始より前まで。** 詳細計測、実用構成の性能検証・改善、既存の非OS境界の検査を進める。以下の工程3〜6は将来の依存関係を示すだけで、TSF実装・OS登録・実キー操作・IME配布への着手指示ではない。Windows入力方式を変更しない。

## 現在地と責務

本体はNode非依存Core、system4、AppContainer/Wasmtime Worker、明示許可・失効、辞書/ネットワークbroker、秘密管理、公式48パッケージの導入、Windows配布アプリ、基本タイムラインまで実装済み。小さな同梱辞書の約0.6秒という既存測定は実用IME速度の達成ではない。Windows TSFへのOS登録・キー入力・未確定表示・対象文書への確定は未実装。

| リポジトリ | 所有するもの |
| --- | --- |
| [DIY_IME2](https://github.com/pitapa79/DIY_IME2) | Core、system/OS境界、Host/broker/Worker、権限、エディター、TSF、配布と診断 |
| [DIY_IME2_node](https://github.com/pitapa79/DIY_IME2_node) | 変換・辞書・候補評価などの処理Node、Node側テスト、パッケージ、固定SDKの取り込み |

処理Nodeを本体へ戻さない。Node側の `sdk/runtime` は固定snapshotであり、共通APIの二重開発場所ではない。SDK変更は本体で契約を定義・検証してから別Issue/PRで取り込む。Node側では最新のAGENTS.mdと開発・Issue運用規則を読む。公式採用・同梱・外向け仕様と、技術的実装を区別する。

工程1は計測のために必要な単位へ分割してよい。部分PRは `Refs #306` とし、全計測やIME全体の完成と呼ばない。第4段階の任意SDK v2内部工程は、固定v1/公式48パッケージのbytesを維持してNode側で段階導入する。これはTSF入力経路そのものとは別工程であり、全Nodeに内部計測を必須にしない。

IME化前の引継ぎでは、Host/Workerの内訳と律速、最適化前後の互換性・負荷、実用辞書の検証範囲、SDK v2の導入状況、未決定仕様をまとめる。TSFがない状態の測定をReference IMEの実経路の合格に置き換えない。

## 仕様の決定点

次の項目は既存Issueでも未決定。実装担当の都合で製品仕様として固定せず、狭い選択肢・理由・試験可能な案をIssueへ記録して決定する。今回の自律作業・マージ許可は、正式fixtureや権限を弱める理由にはしない。

| 決定点 | 決定が必要な時点 |
| --- | --- |
| 入力/変換/候補/確定の操作、配列やショートカット、設定方法 | OSキーを消費する実装の前 |
| フォーカス移動・文書切替・無効化時の未確定文字列と候補 | TSF composition/編集Session接続の前 |
| 自動保護の検出範囲・判定不能時、手動保護の開始/解除/維持 | #221/#222の実装の前 |
| Reference構成・実用辞書・候補数・配布ライセンス | 実用性能の合否判定と同梱の前 |
| 対応Windows/アプリ、公開署名・更新/復旧方針 | 公開版の配布前 |

Native Nodeの隔離解除・高権限、SEC台帳全196項目の採用、学習履歴や監査の保存方針はこの計画の一括採用対象ではない。

## 実行と完成判定

1タスク=1Issue=1専用branch/worktree=1PR。既存の完了資産を再実装せず、開始SHA、担当範囲、検査と制限をPRに残す。依存PRは `Refs`、受け入れ条件を満たす最終PRは `Closes`。担当外PRを巻き込まず順に統合する。自己レビューはCOMMENTであり独立承認と呼ばない。

Rustは担当検査の後に `cargo test --locked`、fmt、clippyを行い、UI/bridge変更ではCLI buildと `editor/` のtest/buildを行う。実Wasm・隔離・取消・実終了の検査とTSF/実アプリの検査を区別する。文書のみならリンクと差分を確認する。

IME化の完成は、実TSFを通した文字入力・候補操作・対象文書への確定、旧結果/誤文書/二重確定の拒否、保護入力の非配送、異常終了からの復旧、明示的な導入/解除が、記録したWindows/アプリ範囲で通った時点で判定する。独立アプリの成功やモックだけでは完了にしない。速度目標未達や未検証アプリは別に明記する。
